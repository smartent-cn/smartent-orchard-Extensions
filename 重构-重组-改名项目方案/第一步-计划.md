## 3. 目录与 Legacy 关系

```text
仓库根/
  build/                    ← Smartent 全局 MSBuild（新旧工程共用）
  Smartent-src/             ← 迁移目标树（本步仅空架 + README）
  src/                      ← Legacy，本步全部保留
  test/                     ← Legacy
  tools/                    ← Legacy（分析器 M1 仍从 tools 引用）
  Lombiq.OSOCE.sln          ← 仍为主 sln，本步不改名
```

**长期终态**：`Smartent-src/` 含全部产品代码；`src/`、`test/` 中 Lombiq 树 **删尽**。过渡期允许双树并存，但 **禁止** 同一逻辑长期维护两份拷贝。

## 4. 单项目迁移标准流程（第二步起强制执行）

```mermaid
flowchart LR
  A[在 Smartent-src 建立新 csproj] --> B[加入主 sln]
  B --> C[改下游 ProjectReference]
  C --> D[build + 约定测试]
  D --> E[删 src 对应 Legacy 目录]
```

| 步骤 | 操作 | 负责人检查 |
|------|------|------------|
| 1 | 复制或移动源码到 `Smartent-src/...`（优先 `git mv` 保留历史） | 路径符合 [Smartent-src/README](../Smartent-src/README.md) |
| 2 | 重命名 csproj、AssemblyName、RootNamespace、`PackageId` 为 Smartent | 与 [项目清单](项目清单.md) 草案一致 |
| 3 | 主 sln 添加新项目、移除旧项目项 | 无悬空引用 |
| 4 | 全局替换 **直接** `ProjectReference` 旧路径 → 新路径 | `rg` 旧路径为零 |
| 5 | `dotnet build` 主 sln；跑该项目相关测试 | 绿 |
| 6 | 删除 Legacy 文件夹 | 父目录无其它工程时才删空父级 |
| 7 | 更新 `项目清单.md` 状态 | 可审计 |
